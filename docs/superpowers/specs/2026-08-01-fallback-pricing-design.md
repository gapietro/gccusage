# Offline pricing fallback — design

Date: 2026-08-01
Issues: [#82](https://github.com/gapietro/gccusage/issues/82) (P1, COR-001), [#93](https://github.com/gapietro/gccusage/issues/93) (P2, COR-004)

## Problem

`FALLBACK_PRICING` in `src/data/pricing-fetcher.ts` holds three model ids from
2024–2025. None matches any model in current use, so a failed pricing fetch
prices every model at nothing: the session cost renders `$0.00` and the
burn-rate segment disappears, indistinguishable from a genuinely free session.

Two mechanisms produce the zero, and fixing either alone leaves the bug:

1. **The table is stale.** It was hand-maintained and nothing failed when it
   aged out.
2. **`calculateCostByModel` skips unpriced models silently** rather than
   signalling, so the zero propagates into the session total, today's total,
   and the daily store with no visible degradation.

A third defect sits in the same function and makes the fallback useless even
when it is fresh: `fetchPricing` merges `FALLBACK_PRICING` only on the
fetch-success path. The cache-hit path returns the cached table raw, and the
cache stores the un-merged fetch — so from run 2 onward the fallback
contributes nothing. That is issue #93, folded in here because it is three
lines of the function being rewritten.

## Non-goals

`claude-opus-5[1m]` prices at standard Opus 5 rates. The 1M-context premium
tier is absent from LiteLLM, and inventing rates locally would be a worse
error than the known approximation. Filed as a follow-up instead.

## Design

### 1. Generated fallback table

New generated, committed file `src/data/fallback-pricing.ts`:

```ts
// Generated by `npm run pricing` — do not edit by hand.
export const FALLBACK_PRICING: PricingTable = { /* claude-* snapshot */ };
```

It is produced by the same `parseLitellmPricing` the online path uses, so the
offline table can never parse differently from the online one. Today that
yields 25 `claude-*` entries including `claude-opus-5`, `claude-fable-5`, and
`claude-opus-4-6`.

`pricing-fetcher.ts` imports it, drops the inline literal, and exports
`parseLitellmPricing` and `LITELLM_URL` for the generator.

Regeneration follows the existing `config-schema.json` precedent
(`npm run schema`), because `scripts/` cannot import `src/` and a plain-node
generator would have to duplicate the parser:

```
npm run pricing  ->  UPDATE_FALLBACK_PRICING=1 vitest run src/__tests__/fallback-pricing.test.ts
```

The network fetch happens only under that environment variable. A normal
`npm test` never touches the network.

Staleness is caught by the fixture-pinned test below and, at runtime, by the
unpriced marker — not by a clock. An age-based failing test was rejected: it
turns into a suite failure on a day nobody touched the code, on unrelated PRs.

### 2. Merge the fallback on every path (closes #93)

```
cache hit    ->  { ...FALLBACK_PRICING, ...cached }
fetch ok     ->  { ...FALLBACK_PRICING, ...fetched }   (unchanged)
fetch fails  ->  { ...FALLBACK_PRICING }
```

### 3. Unpriced signal

`calculateCostByModel` returns `{ costs, unpriced }` instead of a bare `Map`.
The signature change is deliberate: it forces both call sites to confront the
models being skipped, which is the defect class that produced this bug.
`unpriced` lists only models carrying non-zero tokens — a model with no tokens
contributing zero is not a data loss.

`RenderContext` gains:

| Field | Meaning |
|---|---|
| `unpricedModels: string[]` | models with tokens but no price |
| `sessionCostUncertain: boolean` | the displayed session cost omits unpriced usage |
| `todayCostUncertain: boolean` | the displayed today total omits unpriced usage |

The uncertain flags are true only when the displayed figure actually came from
the pricing table. In `stdin`/`auto` mode the session total comes from
`cost.total_cost_usd` and today's from the daily store; neither is affected by
a missing price, so neither gets a marker.

Rendering:

- `session-cost`, `today-spend`: append `?` → `$0.33?`, `Today: $4.10?`
- `per-model-breakdown`: `Fable 5:$?`, and it no longer returns `null` when
  only unpriced models exist (that case currently renders nothing at all)
- `burn-rate`: unchanged — it already declines rather than printing a
  confident `$0.00/hr`
- `cli.ts` (`gccusage today`): prints a line naming the unpriced models

The `?` costs one column in a rare state; the layout shrink pass absorbs it.

## Testing

- `src/__tests__/fallback-pricing.test.ts`
  - generator mode under `UPDATE_FALLBACK_PRICING=1` (network, opt-in)
  - offline: every model id harvested from `src/__tests__/fixtures/`
    (real-payloads, `sample-transcript.jsonl`, `widget-expectations.ts`)
    resolves through `findPricing(id, FALLBACK_PRICING)`. Resolution, not key
    presence — `claude-opus-5[1m]` has no LiteLLM entry and only lands via the
    fuzzy `model.includes(key)` branch.
  - offline: per-entry sanity — four rates finite and positive, output ≥ input,
    cacheRead ≤ input
- `pricing-fetcher`: cache-hit merges the fallback (#93 regression); a forced
  fetch failure returns a table that prices `claude-opus-5`
- `cost-calculator`: the `unpriced` list
- widget tests for the three `?` renderings
- end-to-end: a forced-offline pipeline render with `costSource: "calculated"`
  yields a non-zero cost — the acceptance criterion stated in #82

Every new test is verified by breaking what it guards, per the repo's
vacuous-tests rule.

## Shipping

`npm run build` with `git add -f dist/index.js` in the same commit — a
src-only commit leaves `git pull` upgraders running the old bundle. Branch,
PR, close #82 and #93, update the `AUDIT.md` ledger.
